# Demos

`docs/BRIEF.md` asks for six required demonstrations. `skyfix-sim` packages them as ten
named scenarios — some of the six have two or three variants — and every one of them has
a fixed random seed, so running the same command twice gives the same numbers.

**Every demo on this page is a simulation.** The sky, the noise, the clock error and the
bias are all generated by `skyfix-sim`, not measured with an instrument. `skyfix simulate`
and `skyfix experiment` always print this themselves, and the browser workbench marks a
simulated session in its header banner and never mixes a simulated number into the parts
of the interface that describe a real one. See `docs/ACCURACY.md` for what "numerical
accuracy" does and does not mean here.

List them yourself with `skyfix demos` (or `skyfix demos --json`); every command below was
run in this worktree to produce the output shown.

| brief demo | scenario name(s) |
|---|---|
| 1. Stationary Philadelphia star fix | `philadelphia-stars`, `philadelphia-stars-real`, `philadelphia-stars-sextant` |
| 2. Good versus clustered geometry | `good-geometry`, `clustered-geometry` |
| 3. One bad observation | `one-bad-sight` |
| 4. Shared clock offset | `clock-offset` |
| 5. Shared altitude bias | `shared-bias` |
| 6. Single sight and two-sight ambiguity | `single-sight`, `two-sight-ambiguous` |

For every scenario, "the headline numbers" below come from

```console
skyfix experiment --demo <name> --repetitions 50
```

which re-simulates the scenario 50 times with fresh seeds, solves each one, and compares
the true error against the uncertainty the solver predicted. Coverage is the fraction of
those 50 runs whose truth fell inside the solver's own nominal 95 % ellipse; under an
honest independent-noise model it should be near 0.95, and three of these six demos are
built to show exactly when it is not.

---

## 1. A stationary Philadelphia star fix

A navigator standing still near Philadelphia (39.9526 N, 75.1652 W) takes several star
sights within a few minutes of 2026-10-01T01:30Z, at bodies spread around the compass
between about 27 and 62 degrees above the horizon — high enough to keep refraction small,
low enough to sight comfortably. Each altitude is off by a small, independent random
amount, under an arcminute, the way a careful sextant observer's readings scatter. This is
the case to read first: it is what a healthy fix looks like, so the next five demos are
recognisable as unhealthy.

Three packaged scenarios cover it: `philadelphia-stars` uses invented "sim-" bodies placed
at chosen altitudes and azimuths (so the result cannot depend on the astronomy provider
being right); `philadelphia-stars-real` runs the identical experiment against six real
navigational stars (Vega, Altair, Arcturus, Deneb, Capella, Polaris) looked up in the
almanac, to show the astronomy and the navigation agree; `philadelphia-stars-sextant`
emits raw sextant readings instead of corrected altitudes, exercising the correction chain.

```console
$ skyfix simulate --demo philadelphia-stars --out-session s.json --out-truth s.truth.json
$ skyfix solve s.json
UNIQUE FIX
Position     39.953130, -75.155885
             39 57.19' N, 075 09.35' W
Uncertainty  sigma north 966.4 m (0.522 NM), sigma east 910.3 m (0.492 NM)
Ellipse 95%  semi-major 2365.6 m, semi-minor 2227.9 m, orientation 2.1 deg clockwise from north
Fit          chi2 2.2305 on 3 degree(s) of freedom, converged after 6 iteration(s)

Residuals
  id        body        Hc deg   Zn deg  resid '    norm  weight
  obs-1     sim-Alpha  58.004530    35.0     0.29    0.36    1.00
  obs-2     sim-Bravo  44.377617   105.4     0.60    0.75    1.00
  obs-3     sim-Charlie 27.127252  171.0     0.50    0.63    1.00
  obs-4     sim-Delta  37.987893   241.4     0.22    0.27    1.00
  obs-5     sim-Echo   60.812562   309.5     0.82    1.03    1.00
```

The truth is 39.9526, -75.1652: the fix lands about 796 m (0.43 NM) from it — a
great-circle distance computed from the two positions on `EARTH_RADIUS_M`, the same
sphere `docs/CONVENTIONS.md` section 1 uses throughout — well inside the 95 % ellipse
(2.37 km by 2.23 km), and every normalised residual is under 1.1 sigma.

**Headline numbers**, `skyfix experiment --demo philadelphia-stars --repetitions 50`:

| statistic | value |
|---|---|
| coverage of the nominal 95 % ellipse | 0.960 (Wilson 95 % interval 0.865 to 0.989) |
| mean error | 1232.1 m (0.665 NM) |
| mean predicted sigma | 1327.6 m (0.717 NM) |
| RMS error / RMS predicted sigma | 1.02 |

Coverage near 0.95 and a ratio near 1.0 are exactly what an honest independent-noise
model should produce. `philadelphia-stars-real` (`skyfix experiment --demo
philadelphia-stars-real --repetitions 50`) gives coverage 0.980, mean error 1092.7 m, mean
predicted sigma 1210.1 m, ratio 1.01 — the same shape of answer against real stars.
`philadelphia-stars-sextant` gives coverage 0.960, mean error 1233.6 m, mean predicted
sigma 1327.6 m, ratio 1.02 — the raw-reading session solves to the same place as the
corrected-altitude one once the correction chain undoes the index error, dip and
refraction.

**In the browser:** Observations tab, "Packaged demos", choose `philadelphia-stars`, "Load
demo", then the Fix tab and "Solve". Look at Position, the North/East nominal
uncertainty, the 95 % ellipse size, and the Residuals table — every residual should sit
under about one sigma. On the Simulator tab, choosing the same scenario and running the
"Coverage experiment" with Repetitions 50 reproduces the table above under its own field
names (Coverage of the 95 % ellipse, RMS true error, RMS predicted sigma, Error ÷ sigma).

## 2. Good versus clustered observation geometry

Two scenarios share everything — the same six stars, the same schedule, the same random
seed, the same one-arcminute noise — except which direction the observer was looking.
`good-geometry` uses all six, spread around the compass; `clustered-geometry` keeps only
the three that fall inside a 30-degree window in the north-east, as if that were the only
clear patch of sky. Every sight still draws a circle of position; three nearly parallel
circles pin down one direction well and say almost nothing about the direction across it.

```console
$ skyfix simulate --demo good-geometry --out-session good.json --out-truth good.truth.json
$ skyfix solve good.json
UNIQUE FIX
Position     39.956014, -75.176081
Ellipse 95%  semi-major 3151.5 m, semi-minor 2286.5 m, orientation 123.9 deg clockwise from north
Conditioning condition number 1.38, max azimuth gap 92.5 deg

$ skyfix simulate --demo clustered-geometry --out-session bad.json --out-truth bad.truth.json
$ skyfix solve bad.json
UNIQUE FIX
Position     39.957717, -75.179948
Ellipse 95%  semi-major 9278.0 m, semi-minor 1888.6 m, orientation 124.4 deg clockwise from north
Conditioning condition number 4.91, max azimuth gap 331.6 deg
Warnings
  - The sight geometry is poor: condition number 4.9 with a 332 degree gap between
    azimuths, so the fix is far weaker across that gap than along it.
```

Same stars, same noise, same seed — the clustered ellipse's long axis is nearly three
times the spread scenario's (9278 m against 3152 m), the condition number goes from 1.38
to 4.91, and the solver says outright that the geometry is poor. Neither fix is wrong; the
clustered one is honestly far less certain.

**Headline numbers**, `skyfix experiment --demo <name> --repetitions 50`:

| statistic | good-geometry | clustered-geometry |
|---|---|---|
| coverage of the nominal 95 % ellipse | 1.000 (Wilson 0.929 to 1.000) | 0.960 (Wilson 0.865 to 0.989) |
| mean error | 1374.9 m (0.742 NM) | 3476.9 m (1.877 NM) |
| mean predicted sigma | 1590.7 m (0.859 NM) | 3867.6 m (2.088 NM) |
| RMS error / RMS predicted sigma | 0.93 | 1.05 |

Both scenarios cover their own ellipse correctly — the model is honest either way — but
the clustered ellipse the solver reports is more than twice the size of the spread one, for
the same six stars and the same noise.

**In the browser:** load `good-geometry`, Solve on the Fix tab, note the ellipse
dimensions and condition number, then load `clustered-geometry` and repeat. The Position
plot draws both fixes and their circles of position on a graticule, so the "long, thin"
shape of the clustered ellipse — and the near-parallel circles that cause it — is visible
directly.

## 3. One bad observation

Five sights, four ordinary and one wrong: the third reads 8 arcminutes too high, the kind
of mistake that comes from misreading the sextant drum. Weighted least squares does not
discard it — it splits the difference, so the fix moves and every residual grows a little,
while the bad sight keeps the largest one.

```console
$ skyfix simulate --demo one-bad-sight --out-session bad.json --out-truth bad.truth.json
$ skyfix solve bad.json
UNIQUE FIX
Position     39.893873, -75.156577
Fit          chi2 172.4247 on 3 degree(s) of freedom, converged after 7 iteration(s)

Residuals
  id        body        Hc deg   Zn deg  resid '    norm  weight
  obs-1     sim-Alpha   57.955667  34.9     2.29    4.59    1.00
  obs-2     sim-Bravo   44.207295 105.2    -1.75   -3.50    1.00
  obs-3     sim-Charlie 27.124051 170.5     4.97    9.93    1.00
  obs-4     sim-Delta   38.521889 240.8    -1.80   -3.60    1.00
  obs-5     sim-Echo    61.367323 309.8     2.62    5.24    1.00
```

The truth is 39.9526, -75.1652 — this fix is 6.567 km (3.546 NM) from it, by the same
great-circle calculation — and `obs-3`, the sight that was actually wrong, carries the
largest residual (4.97′, nearly 10 sigma) but every other residual is inflated too.
Turning on robust weighting pulls the fix back and says so:

```console
$ skyfix solve bad.json --robust
UNIQUE FIX
Position     39.944587, -75.166198
Residuals (obs-3)  resid ' 8.04   weight 0.09
Warnings
  - Robust (Huber) weighting downweighted obs-3, so the covariance and ellipse below are
    approximate rather than exact.
```

With `obs-3` downweighted to a tenth of its original influence, the fix moves from 6.567 km
off truth to 0.894 km (0.483 NM), at the declared cost of an approximate covariance.

**Headline numbers**, `skyfix experiment --demo one-bad-sight --repetitions 50` (robust
weighting off, matching the plain `skyfix solve` above):

| statistic | value |
|---|---|
| coverage of the nominal 95 % ellipse | 0.000 (Wilson 95 % interval 0.000 to 0.071) |
| mean error | 6249.1 m (3.374 NM) |
| mean predicted sigma | 829.5 m (0.448 NM) |
| RMS error / RMS predicted sigma | 7.57 |

Coverage of zero is the point: one bad sight, left in and un-downweighted, puts the fix
about 7.6 times further out than the ellipse it reports.

**In the browser:** load `one-bad-sight`, Solve, and look at the Residuals table — one
value stands far outside the rest, which is the signal something is wrong with a *sight*
rather than with the position. Tick "Robust (Huber) weighting" on the Fix tab and solve
again: the position moves back toward the centre of the other four sights' circles, and a
CAUTION warning names the downweighted sight.

## 4. A shared clock offset

Five perfect sights — no noise, no bias, no blunder — taken with a watch that is exactly
one minute fast. The sky turns 15.04 degrees an hour, so a minute of clock error moves
every star's tabulated position 0.2507 degrees west, and the only way to reconcile that
with what was actually measured is to place the observer 0.2507 degrees of longitude
further west too.

```console
$ skyfix simulate --demo clock-offset --out-session c.json --out-truth c.truth.json
$ skyfix solve c.json
UNIQUE FIX
Position     39.952600, -75.415884
             39 57.16' N, 075 24.95' W
Fit          chi2 0.0000 on 3 degree(s) of freedom, converged after 3 iteration(s)

Residuals
  obs-1 .. obs-5   resid ' 0.00 (every one)
```

The truth is 39.9526, -75.1652. Latitude comes back exact to six decimals; longitude is
0.2507 degrees (about 21.3 km, 11.5 NM) west of the truth, and **every residual is
exactly zero** — the data is perfectly self-consistent, because clock error and longitude
are the same unknown for star sights (`docs/CONVENTIONS.md` section 6). The solver does
not attempt to estimate a clock offset; declaring what you actually know about the clock
widens the answer instead of moving it:

```console
$ skyfix solve c.json --clock-sigma 60
Uncertainty  sigma north 1205.4 m (0.651 NM), sigma east 21384.2 m (11.547 NM)
             clock contribution to east 21353.8 m (11.530 NM)
Ellipse 95%  semi-major 52343.1 m, semi-minor 2950.6 m, orientation 90.0 deg clockwise from north
Warnings
  - Clock error and longitude are the same quantity for these sights, so the clock offset
    was not estimated; the stated uncertainty was propagated instead as 21354 metres of
    extra east-west uncertainty.
```

The fix does not move; the ellipse grows to 52.3 km along its east-west axis and now
covers the truth.

**Headline numbers**, `skyfix experiment --demo clock-offset --repetitions 50` (without
`--clock-sigma`, so the ellipse is not told about the offset):

| statistic | value |
|---|---|
| coverage of the nominal 95 % ellipse | 0.000 (Wilson 95 % interval 0.000 to 0.071) |
| mean error | 21353.8 m (11.530 NM) |
| mean predicted sigma | 1659.1 m (0.896 NM) |
| RMS error / RMS predicted sigma | 12.87 |
| mean residual RMS | 0.000 arcminutes |

Zero coverage with zero residuals is the whole demonstration: nothing in the data looks
wrong, and the fix is 21 km out anyway.

**In the browser:** load `clock-offset` on Observations, Solve on the Fix tab — the
Residuals table reads all zero. Then on the Simulator tab set "Reported clock uncertainty"
to 60 seconds under "What the session tells the solver" and re-run; the Fix tab's ellipse
stretches east-west to cover the same, unmoved position.

## 5. A shared altitude bias

Twenty-four sights of three stars, a minute apart, from an instrument that reads 3
arcminutes too high on *every* sight. The random part of each reading is small, a third of
an arcminute — twenty-four sights is plenty to average that down — but nothing averages
away an error that is identical on every sight.

```console
$ skyfix simulate --demo shared-bias --out-session s.json --out-truth s.truth.json
$ skyfix solve s.json
UNIQUE FIX
Position     39.947343, -75.082460
Uncertainty  sigma north 177.5 m (0.096 NM), sigma east 147.7 m (0.080 NM)
Ellipse 95%  semi-major 435.5 m, semi-minor 360.3 m, orientation 7.3 deg clockwise from north
Fit          chi2 129.5338 on 22 degree(s) of freedom, converged after 6 iteration(s)

Residuals (first of 8 rounds of 3; the pattern repeats)
  obs-1   sim-NorthEast   resid ' 0.84   weight 1.00
  obs-2   sim-East        resid '-0.59   weight 1.00
  obs-3   sim-SouthEast   resid ' 0.90   weight 1.00
```

The truth is 39.9526, -75.1652: this fix is 7.072 km (3.819 NM) from it by great-circle
distance — close to the 7015.56 m (846.45 m south, 6964.31 m east) that `docs/SIMULATOR.md`
section 6 derives in closed form, with no solver involved, from these sights' own azimuths
— while the reported 95 % ellipse is well under a kilometre across, and every residual
stays under about one arcminute: the bias has been absorbed into the *position*, not left
visible in the leftovers.

**Headline numbers**, `skyfix experiment --demo shared-bias --repetitions 50`:

| statistic | value |
|---|---|
| coverage of the nominal 95 % ellipse | 0.000 (Wilson 95 % interval 0.000 to 0.071) |
| mean error | 7028.7 m (3.795 NM) |
| mean predicted sigma | 230.9 m (0.125 NM) |
| RMS error / RMS predicted sigma | 30.45 |
| mean residual RMS | 0.745 arcminutes |

An error thirty times the predicted sigma, with residuals that look entirely ordinary —
more sights shrink the ellipse and do nothing for the answer.

**In the browser:** load `shared-bias`, Solve, and compare the North/East nominal
uncertainty against how far the plotted fix sits from where the assumed position and the
stars would suggest. On the Simulator tab, "Shared altitude bias" is set to 3.0
arcminutes under "What is actually done to the data (truth)" — change it to 0 and re-solve
to see the same geometry recover the truth almost exactly.

## 6. One sight, and the two-sight ambiguity

`single-sight` is one sight of one star: it constrains the observer to a circle about
2700 NM across and nothing more. `two-sight-ambiguous` is two sights of two stars 90
degrees apart in bearing — the best possible two-sight geometry — whose circles cross at
two points that fit the data equally well.

```console
$ skyfix simulate --demo single-sight --out-session one.json --out-truth one.truth.json
$ skyfix solve one.json
UNDERDETERMINED
Reason  1 usable sight(s): one altitude constrains the observer to a circle of position,
        not to a point
Circles of position
  obs-1  sim-Alpha  GP 56 51.74' N, 009 00.49' W  zenith distance 45.0000 deg, radius 2700.0 NM

$ skyfix simulate --demo two-sight-ambiguous --out-session two.json --out-truth two.truth.json
$ skyfix solve two.json
AMBIGUOUS: 2 CANDIDATES
Candidate 1  Position  6.248595, 7.324286     (06 14.92' N, 007 19.46' E)
Candidate 2  Position  39.952600, -75.165200  (39 57.16' N, 075 09.91' W)
These observations cannot distinguish the 2 candidates.
```

Candidate 2 is the truth (39.9526, -75.1652); candidate 1 is a real second intersection of
the same two circles, in Nigeria, about 8916 km (4814 NM) away by the great-circle
distance between the two candidate positions (`skyfix_core::units::EARTH_RADIUS_M`,
section 1 of `docs/CONVENTIONS.md`) — and the tool reports both with no ellipse and no
preference. Both commands exit 0 — an ambiguous or underdetermined result is the *correct*
answer to an under-constrained question, not a solver failure.

**Headline numbers:** neither scenario has one. `skyfix experiment --demo single-sight
--repetitions 50` runs all 50 repetitions to `underdetermined` and `skyfix experiment
--demo two-sight-ambiguous --repetitions 50` runs all 50 to `ambiguous`; both print
"Nothing was scored, so there is no statement to make about the uncertainty model" and
exit 3. That is by design — coverage, mean error and predicted sigma are only defined for
a unique fix with a covariance, and inventing numbers for an under-constrained case would
be exactly the false precision this project exists to avoid.

**In the browser:** load `single-sight`, Solve — the Result reads "Underdetermined — no
position" with a CAUTION explaining that no ellipse is drawn because there is no point
fix. Load `two-sight-ambiguous` and Solve — the Result lists both candidates under
"Ambiguous" with the same caution. The Position plot draws the circle (or both circles)
directly so the geometry is visible, not just stated.
